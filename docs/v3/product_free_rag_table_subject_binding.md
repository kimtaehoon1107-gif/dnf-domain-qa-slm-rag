## 0. 문제

### A6-7 원문

```
브레이커
- 타이드 바운드 - 쿨타임이 감소합니다. (20초 → 18초)     ← 골드 1
- '질풍' 스킬 개화 옵션이 변경됩니다.                    ← 표의 주어
[TABLE]
| 변경 전 | 변경 후 |
| [타이드 바운드] 적 타격 시 … 기본 쿨타임 12초로 변경 … | [타이드 바운드] … 기본 쿨타임 9초 로 변경 … |
[/TABLE]                                                ← 골드 2: 질풍 개화 12→9
- '격랑' 스킬 개화 옵션이 변경됩니다.
[TABLE] … [/TABLE]
```

표 셀 안의 `[타이드 바운드]`는 **질풍 개화 옵션이 영향을 주는 스킬 이름**이며
표의 주어가 아닙니다. 표의 주어는 직전 줄 `- '질풍' 스킬 개화 옵션이
변경됩니다.` 입니다.

### 모델이 실제로 받은 근거

```
text    : "| [타이드 바운드] … 12초로 변경 … | [타이드 바운드] … 9초 로 변경 … |"
context : "업데이트 > 개선 및 변경 사항 > 표 헤더: | 변경 전 | 변경 후 |"
relevance: 0.992  (최고점)
```

**`질풍 개화 옵션`이 근거 어디에도 없습니다.** 모델은 행 안의
`[타이드 바운드]`를 주어로 읽고 `타이드 바운드 12초 → 9초`라고 답했습니다.

**이것은 생성 오류가 아닙니다.** 주어진 근거만 보면 합리적인 독해입니다.
verifier·프롬프트·관계 가드로는 고칠 수 없습니다.

### 원인

`simple_evidence_refs.py::_chunk_atomic_units()`가 표 행에 붙이는 맥락:

```python
context = heading_path + "표 헤더: {table_header}" + optional "표 대상: {table_subject}"
```

`table_subject`는 행 텍스트에 다음 **하드코딩 라벨**이 있을 때만 설정됩니다.

```python
("아이템명", "상품명", "판매물품", "판매목록", "구분")   # simple_evidence_refs.py:288 부근
```

세리아샵·이달의아이템 표에는 맞지만 업데이트 패치노트 표에는 없습니다.
그리고 **`[TABLE]` 직전 줄은 어떤 경우에도 캡처되지 않습니다.**

## 1. 범위 (Claude 실측)

```
전체 [TABLE] 블록              1,532
라벨 컬럼 있음(현재 캡처됨)        560  (36.6%)
직전 도입문 있음                1,258  (82.1%)
라벨도 도입문도 없음               170  (11.1%)
```

**972개(63.4%) 표가 현재 주어 없이 근거로 나갑니다.**

라벨 없이 도입문만 있는 표의 예:

```
[dnf_notice]     이미 진행 중이오니 시간 안내 드립니다.
[dnf_game_guide] 던전이 제공되는 보상으로 3단계 달성 시 보상을 모두 획득할 수 있습니다.
[dnf_game_guide] 난이도 정보
[dnf_seria_shop] 10. 아바타(남)
[dnf_seria_shop] 11. 무기
```

마지막 두 개처럼 **도입문이 짧은 항목 번호일 수도 있습니다.** 유용하지만
문장이 아닙니다. 필터 설계에서 고려하십시오.

## 2. 요구사항

### 핵심

`[TABLE]` 직전의 도입문을 표 행의 `표 대상`으로 캡처하십시오.

```
표 도입문 선택 규칙 (구조로만, 도메인 어휘 금지):
  1. [TABLE] 직전의 비어 있지 않은 줄부터 위로 탐색
  2. 다음은 건너뛰지 말고 즉시 중단 (주어가 아님)
       · 다른 표의 [/TABLE]
       · 표 행 (| 로 시작하고 | 로 끝남)
  3. 다음은 도입문으로 쓰지 않음
       · 헤딩 줄 (# 로 시작) — 이미 heading_path에 있음
       · 각주·단서 줄 (※, * 로 시작)          ← 아래 주의 참조
  4. 길이 상한을 두어 문단 전체가 딸려오지 않게 할 것
```

기존 라벨 기반 `table_subject`는 **제거하지 말고 유지**하십시오. 표 안의
주어 컬럼과 표 밖의 도입문은 서로 다른 정보이며, 둘 다 있으면 둘 다
넣으십시오.

```
context = heading_path
        + "표 헤더: {table_header}"
        + "표 도입: {introducer}"        ← 신규
        + "표 대상: {table_subject}"     ← 기존 유지
```

### ⚠️ 각주 오선택 주의 — 실제 사례가 있습니다

빌드타임 경로(`build_table_atomic_facts.py`)가 이미 같은 실수를 했습니다.

```json
// table_atomic_facts_v3.2 … line 1636 (아라드 패스 표)
"subject":       "* '무제한 투신의 함성 포션[기간제]'는 결투장, 마을, 싸우자, 수련의 방 …",
"table_caption": "* '무제한 투신의 함성 포션[기간제]'는 결투장, 마을, 싸우자, 수련의 방 …",
"row_text":      "| | 종말의 계시 8개 / 10개 / 16개 / 16개 | 만들어진 신 나벨 - 싱글 / 매칭 / 노말 / 하드 |"
```

**직전 줄이 각주였고 그게 주어로 들어갔습니다.** 표의 실제 주어는
`아라드 로얄 패스 캐릭터 지정 시 콘텐츠 추가 보상`입니다.

→ `※`, `*`로 시작하는 줄은 도입문에서 제외하십시오.
→ 제외 후 위로 더 탐색할지, 도입문 없음으로 둘지는 **S1 측정 결과를 보고
   결정**하십시오. 추측으로 정하지 마십시오.

### 🔒 하지 말 것

- **`display_text`를 바꾸지 마십시오.** `chunk_id`가 바뀌면 A6·A5·sealed64·
  existing32·new_claim32의 골드 좌표가 전부 무효화됩니다.
- **코퍼스를 재빌드하지 마십시오.**
- `unit`의 `text`, `start_char`, `end_char`를 바꾸지 마십시오.
  **`context_text`만 바뀝니다.**
- 빌드타임 경로(`build_table_atomic_facts.py`)는 이번 범위 밖입니다.
  각주 오선택은 기록만 하고 별도 라운드로 넘기십시오.
- 다른 가드(`_cross_parent_*`, `_normative_relation_supported`, 헤더 필터,
  채점기)를 건드리지 마십시오.
- 스킬명·아이템명·문서명 허용목록을 만들지 마십시오.

## 3. ⚠️ context_text는 검색 점수에 영향을 줍니다

`context_text`는 프롬프트에만 쓰이는 게 아닙니다.

```
question_relevance_score 계산에 포함됨
_normative_relation_supported()가 title + context_text + text 를 이어붙여 검사
```

**따라서 이 변경은 pack 선택 순서와 일부 가드 판정을 바꿀 수 있습니다.**
좌표는 안 바뀌지만 **어떤 unit이 뽑히는지는 바뀔 수 있습니다.**

전건 스캔에서 이 점을 반드시 확인하십시오.
