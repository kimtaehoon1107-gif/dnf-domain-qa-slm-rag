## 1. slot 2 — 질문에 연도가 없어 기준일과 1년 어긋남 🔴

```
문서 게시일 : 2025-08-12
평가 기준일 : 2026-08-04 (as_of)
현재 질문   : "8월 12일 퍼스트서버 초기화 점검은 몇 시에 시작하고
              서버는 어느 날 다시 열릴 예정이었어?"
```

2026-08-04 기준으로 "8월 12일"은 **8일 뒤(2026-08-12)**로 읽히는 게 자연스럽지만,
정답은 1년 전 문서입니다.

**코퍼스 상황 확인 결과**:
```
"8월 12일" 관련 공지 : 2025-08-12 하나뿐 (2026년 것 없음)
코퍼스 게시일 범위    : 2011-09-17 ~ 2026-07-16
```
즉 모델이 **"2026년 8월 12일 정보는 없습니다"라고 답하면 그게 더 정직한 답**
이며, 정답/오답 판정이 불가능해집니다.

### 조치

```
질문 앞에 "2025년"만 추가:
  "2025년 8월 12일 퍼스트서버 초기화 점검은 몇 시에 시작하고
   서버는 어느 날 다시 열릴 예정이었어?"
```

**근거·정답·문서·차원은 그대로 유지**하십시오. 문항 자체는 정상이며 모호성만
제거하면 됩니다. `temporal_role`의 난이도(시작 시각 vs 재오픈일 구별)는
연도를 붙여도 그대로입니다.

**참고 — slot 7은 수정 불필요**: 문서가 2026-06-17이고 코퍼스의 "6월 18일"
공지가 전부 2026년이라 모호하지 않습니다. (같은 날짜 공지가 5건 있어 문서
선택 난이도가 있는데, 질문에 "브레이커 조정"이 명시돼 좁혀집니다.)

**일관성 참고**: 새로 만든 slot 29~32는 전부 연도를 명시했습니다
("2025년 8월…", "2026년 7월…", "2025년 10월…"). slot 2만 빠져 있었습니다.

## 4. slot 21 — sealed64 slot48과 **사실 중복** 🔴

자동 좌표 검사는 통과했지만(좌표가 달라서), **묻는 사실이 동일**합니다.

```

                   그 기간이 지나면 이의신청을 할 수 있어?"
                   → retention_period = "90일"

[sealed64 slot48] "운영정책상 이용제한 근거 데이터는 며칠 동안 보유해?"
```

**같은 문서·같은 사실·같은 답**입니다. slot 29(v1)에서 지적했던 것과 정확히
같은 유형 — 좌표만 바꾸면 통과하는 자동 검사의 한계입니다.

### 조치

**요구 1(`retention_period` = 90일)을 현재 운영정책의 다른 사실로 교체**
하십시오. 요구 2(`available` = false, 기간 경과 시 이의신청 불가)는 같은
문장에서 파생되므로 함께 재구성이 필요합니다.

교체 시 확인할 것:
- sealed64 41~48, new_claim32의 정책 문항들과 **사실 단위로** 겹치지 않을 것
