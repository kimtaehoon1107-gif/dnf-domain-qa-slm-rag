# 지시서 — 절 분해 실패 선행 진단 (W6 3분할 전)

작성: 2026-08-05 · 대상: Codex
성격: **진단 전용. 런타임 수정 금지. Qwen 호출 0회.**
선행: W6 waterfall (`product_free_rag_w6_relation_waterfall_v2_20260805.jsonl`)

---

## 0. 왜 3분할 전에 이걸 먼저 하는가

Codex가 제안한 W6 3분할(검색 / pack 선택 / 관계 역할)의 **축은 맞습니다.**
증상이 드러난 위치를 정확히 국소화했습니다.

그런데 W6 로그의 `question_clauses` 필드를 보고 5개 질문을 직접 돌려보니
이런 결과가 나왔습니다.

```
              explicit_question_clauses()   kiwi_independent_requirement_queries()
A6 slot  1              2                            0      ← 실패
A6 slot  2              2                            2      ← 유일하게 성공
A6 slot  4              2                            0      ← 실패
A6 slot  7              2                            0      ← 실패
A6 slot 22              2                            0      ← 실패
```

`explicit_question_clauses()`는 **5개 전부 정확히 2절로 분해**합니다.
`kiwi_independent_requirement_queries()`는 **slot 2에서만 성공**합니다.

그리고 파이프라인은 kiwi 결과만 씁니다.

```python
# src/v3/product_free_rag.py:1898 부근
kiwi_queries = kiwi_independent_requirement_queries(normalized)
effective_requirement_queries = kiwi_queries or None          # 0이면 None
atomic_reserve_per_query = 3 if len(kiwi_queries) > 1 else 1  # 3 → 1
```

**kiwi가 0을 반환하면 질문 전체가 한 덩어리 검색 표면이 되고, 요구별 근거
예약도 3에서 1로 줄어듭니다.**

이 한 가지로 W6가 "서로 다른 단계"라고 분류한 것들이 설명됩니다.

| slot | W6 분류 | 가설 상 상류 원인 |
|---:|---|---|
| 22 | 초기 검색 누락 | 통합 검색 → "버그 제보" 이벤트 공지가 pool 점령 |
| 4 | pack 선택 누락 | reserve 1 → 신고 절차 항목이 자리를 못 얻음 |
| 1 | 관계 오연결 | 퀵계좌이체·네이버페이가 한 pack에 섞임 |
| 7 | 관계 오연결 | 타이드바운드·질풍개화가 한 focus |
| 2 | 관계 오연결 | **kiwi 성공** → 별도 원인 |

**kiwi가 성공한 유일한 슬롯만 다른 이유로 실패했습니다.**

이게 맞으면 3개 실험이 1개 수정으로 줄어듭니다. 틀리면 그때 3분할로 갑니다.
**이 진단은 한두 시간이면 끝나고 Qwen을 부르지 않습니다.**

### ⚠️ 표본 5개로 결론 내리지 말 것

이 관찰은 **n=5**입니다. 이 프로젝트는 소수 프로브에 두 번 당했습니다.

```
Kiwi 4케이스 프로브  4/4 깨끗  →  실제 정밀도 10.7%
BGE 7케이스 프로브   7/7 깨끗  →  142 claim에서 임계값 부재
```

**그래서 S1(전수 스캔)이 이 진단의 핵심이고, S3(shadow)보다 먼저입니다.**
S1에서 판별력이 없다고 나오면 S2·S3는 하지 마십시오.

## 1. 실험 S1 — 전수 스캔 (판별력 확인) 🔴

### 대상

```
data/v3/evaluation/product_free_rag_a6_frozen_9405401d….jsonl        (32)
data/v3/evaluation/product_pipeline_user10_v2_adaptive_20260805.jsonl (10)
A5 sealed 32
existing32
new_claim32
sealed64
```

### 측정

각 질문에 대해:

```
explicit_n   = len(explicit_question_clauses(q))
kiwi_n       = len(kiwi_independent_requirement_queries(q))
requirement_n = len(frozen["requirements"])          (골드가 있는 세트만)
decomposition_gap = (explicit_n >= 2) and (kiwi_n == 0)
```

그리고 **사람 판정 결과와 교차**하십시오.

```
                     정답 문항   오답 문항
decomposition_gap 참    a           b
decomposition_gap 거짓  c           d
```

A6는 사람 판정 19/32(정답 19 / 오답 13)를 쓰고, USER10은 확정 판정
7정답 / 2오답 / 1보류를 씁니다. 보류는 제외하십시오.

### 판정 기준 (사전 등록)

| 결과 | 해석 | 다음 |
|---|---|---|
| gap이 오답에 **뚜렷하게 몰림** (오답 gap율이 정답 gap율의 2배 이상) | ✅ 후보 원인 | S2 진행 |
| gap이 정답·오답에 **고르게 분포** | ❌ **판별력 없음** | **여기서 중단.** W6 3분할로 복귀 |
| gap 자체가 거의 없음 (전체 5% 미만) | ❌ n=5가 우연 | 중단, 3분할로 복귀 |

**두 번째·세 번째면 S2·S3를 하지 말고 즉시 보고하십시오.** 원인 가설이
틀린 것이며, 그 자체가 유용한 결과입니다.

## 2. 실험 S2 — kiwi가 0을 반환하는 조건 특정 🟡

S1이 통과했을 때만.

`kiwi_independent_requirement_queries()`가 어떤 구조에서 0을 내는지
문장 유형별로 정리하십시오.

```
관찰된 성공 예 (slot 2):
  "…점검은 몇 시에 시작하고 서버는 어느 날 다시 열릴 예정이었어?"
관찰된 실패 예:
  "…한도와 하루 결제 횟수 제한을 한꺼번에 알려줘."        (slot 1)
  "…어떤 메뉴로 신고해야 하고, …어떤 제재가 적용돼?"        (slot 4)
  "…쿨타임은 어떻게 줄었고, …몇 초로 바뀌었어?"            (slot 7)
  "…어디에 제보해야 하고, …정확히 며칠이야?"               (slot 22)
```

**가설을 세우되 여기서 코드를 고치지 마십시오.** 어떤 형태소 패턴에서
독립절 판정이 실패하는지 기록만 합니다.

- 도메인 어휘와 무관한 **문법 구조**로만 기술하십시오.
- 질문 문장을 허용목록으로 만들지 마십시오.

## 3. 실험 S3 — explicit fallback shadow 🟡

S1·S2가 통과했을 때만.

### 설계

**런타임을 바꾸지 말고**, 진단 스크립트 안에서만 다음 두 조건의 검색을
비교하십시오.

```
[조건 A 현행]   requirement_queries = kiwi_queries or None
[조건 B shadow] requirement_queries = kiwi_queries or explicit_question_clauses(q)
                atomic_reserve_per_query 도 절 수에 맞춰 계산
```

**Qwen은 부르지 않습니다.** 비교 대상은 답변이 아니라 다음뿐입니다.

```
- hybrid_union_count / reranker_candidate_count
- final_candidate_chunk_ids
- evidence_pack 의 ref·chunk_id·text
- 골드 근거(acceptable_evidence_units)가 pack에 들어왔는가   ← 핵심 지표
- 단계별 지연 (특히 candidate_rerank_ms)                    ← 필수
```

### 대상

```
A6 slot 1 · 4 · 7 · 22        (gap 케이스)
A6 slot 2                     (kiwi 성공 대조군)
S1에서 gap이면서 정답이었던 문항 전부   ← 악화 확인용, 빠뜨리지 말 것
```

마지막 줄이 중요합니다. **gap이 있는데도 정답이던 문항이 조건 B에서
나빠지면**, 이 수정은 순이득이 아닙니다.

### 판정 기준 (사전 등록)

| 지표 | 통과 조건 |
|---|---|
| 골드 근거 pack 진입 | slot 1·4·22 중 **2개 이상**에서 새로 진입 |
| 대조군 slot 2 | pack 변화 **없음** (kiwi가 이미 성공하므로) |
| gap-정답 문항 | 골드 근거가 pack에서 **빠지는 문항 0건** |
| `candidate_rerank_ms` | 증가분을 **반드시 수치로 보고** (판정 기준 아님, 기록 필수) |

### ⚠️ 지연 함정

요구별 검색은 리랭커를 요구 수만큼 돌립니다. 이번 라운드 실측:

```
candidate_rerank_ms  4.7초  (질의 1세트 기준, 10문항 전부 고정)
```

절 2개면 **약 +5초**입니다. 이미 p50이 게이트를 못 넘는 상태이므로,
**정확도 개선만 보고 채택하면 지연에서 잃습니다.** S3 보고에 지연 증가분을
반드시 포함하십시오.

## 4. 하지 말 것

1. **런타임 코드를 고치지 마십시오.** 이 라운드는 전부 진단입니다.
   조건 B는 진단 스크립트 안에서만 구성합니다.
2. **Qwen을 부르지 마십시오.** 비교는 후보·pack 수준에서만.
3. **S1이 실패하면 S2·S3를 하지 마십시오.** 가설 기각도 결과입니다.
4. **질문 문장이나 도메인 어휘 허용목록을 만들지 마십시오.**
5. **`_cross_parent_*` 가드, `_normative_relation_supported`, 채점기를
   건드리지 마십시오.** 지난 라운드에서 안정화된 것들입니다.
6. **slot 번호에 접두사를 붙이십시오.** 아래 이름 충돌이 있습니다.

```
A6 slot 4      = 피싱 신고 경로              ← 이 진단의 대상
USER10 slot 4  = 간편잠금 비밀번호 변경       ← 지난 라운드에서 수정됨
```

접두사 없이 "slot 4"라고 쓰면 반드시 누군가 틀린 것을 고칩니다.

## 7. 어느 경우든 반영할 재분류

W6 원본 3분할에서 두 가지를 고쳐야 합니다.

### ① A6 slot 2와 slot 22는 같은 유형입니다

```
slot 2  : E1 = "2025.08.12 14:00"  (문서 게시 타임스탬프, relevance 0.981)
          → 점검 시작 시각으로 답함. 본문은 15시.

slot 22 : E1 문서 = "퍼스트서버 버그 제보 이벤트 당첨자"  published_at 2025-12-04
          → 답변 기한을 "12/4(목)"으로 지어냄. 문서 게시일임.
          → 제보처도 이 이벤트 공지의 "담당부서"를 씀. 정답은 고객센터.
```

**둘 다 문서 메타데이터를 본문 사실로 오인한 것**입니다. W6는 slot 2를
"관계 역할", slot 22를 "검색 누락"으로 나눴지만 같은 실패 유형입니다.

slot 22는 절 분해가 고쳐져 고객센터 근거가 들어와도 **메타데이터 오인은
별도로 남을 수 있습니다.**

### ② A6 slot 7은 생성 문제가 아닙니다

```
E1 text : "| [타이드 바운드] …기본 쿨타임 12초로 변경… | [타이드 바운드] …기본 쿨타임 9초 로 변경… |"
context : "표 헤더: | 변경 전 | 변경 후 |"
relevance: 0.992  ← 최고점
```

**표 행 양쪽이 모두 `[타이드 바운드]`입니다.** 정답은 타이드 바운드 20→18,
질풍 개화 12→9인데 이 근거는 12→9를 타이드 바운드라고 말합니다.

모델이 "타이드 바운드 12→9"라고 답한 것은 **근거에 충실한 결과**입니다.
생성·검증 레이어에서는 고칠 수 없습니다. **표 원자화 문제로 재분류**하고
별도로 다루십시오.

### 재분류 결과

```
그룹 A  절 분해 실패          A6 slot 1 · 4 · 22   ← 이 진단의 대상
그룹 B  문서 메타데이터 오인    A6 slot 2 · 22       ← 별도 라운드
그룹 C  표 원자화 왜곡         A6 slot 7            ← 별도 라운드, 생성 아님
```

slot 22가 A와 B 양쪽에 있는 것은 의도된 것입니다. 두 결함이 겹쳐 있습니다.
