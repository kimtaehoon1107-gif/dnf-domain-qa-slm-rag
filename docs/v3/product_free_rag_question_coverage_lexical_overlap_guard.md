## 0. 배경

Q1/Q2 명시적 커버리지 계약(질문을 표면 항목으로 나누고 각 항목마다
supported/unsupported를 먼저 판단시키는 방식)은 slot 4를 고쳤지만 slot 12는
여전히 실패했습니다 — Qwen이 "연령 확인 절차"(Q2)에 "개인정보 수집·이용 동의"
근거를 의미적으로 맞다고 잘못 판단했습니다(직접 재현 확인).

다음 단계로 제안된 "별도 semantic entailment 모델"을 만들기 전에, **더 싼
어휘 겹침 검사**부터 실험했습니다. 결과는 **부분적으로만 유효**합니다 —
적용 범위를 반드시 좁혀야 합니다.

---

## 1. 실험 방법

기존 `src/v3/simple_evidence_refs.py`의 `_compact_tokens`(2자 이상
한글/영숫자 토큰 추출, 조사 미분리)를 그대로 재사용했습니다. 새 토크나이저는
만들지 않았습니다.

```python
q_tokens = _compact_tokens(question_ref_text) - STOPWORDS
ev_tokens = _compact_tokens(cited_evidence_text)
overlap_ratio = len(q_tokens & ev_tokens) / max(1, len(q_tokens))
```

`STOPWORDS`는 "알려줘/각각/정확한/무엇/뭐야/언제/얼마" 등 질문에 습관적으로
붙는 표현만 최소로 제외했습니다.

---

## 2. 결과 — 효과 있는 경우와 역효과가 나는 경우가 갈립니다

### 2.1 효과 있음: Q1/Q2 계약이 놓친 관계 혼동 (slot 4, 12류)

| 사례 | 정답 겹침비율 | 오답 겹침비율 |
|---|---:|---:|
| slot12 (연령 확인 vs 개인정보 동의) | 0.43 | **0.00** |
| slot4 (할인쿠폰 금액 vs 신규가입 포인트) | 0.67 | **0.00** |

주어가 짧고, 정답/오답 후보가 **서로 다른 개념어**(확인 vs 동의, 쿠폰 vs
포인트)로 구분되는 경우 깨끗하게 갈립니다.

### 2.2 역효과: 긴 주어 반복 + 관용구 정답 (slot 27류)

> **정정(2026-08-04)**: 아래 수치는 **A5 one-shot 실행 당시** 실제로 삭제
> 문장이 선택됐던 상황을 재현한 것입니다. 그 이후 Kiwi 독립 절 검색 +
> evidence reserve 수정이 반영되면서, **slot 27은 지금은 판매 기간(E2)과
> 삭제 시각(E1)을 각각 올바르게 답변합니다** — 라이브로 직접 재확인했습니다.
> 아래 비교는 "이 어휘 겹침 검사를 evidence 선택 단계에 넣으면 안 되는
> 이유"를 보여주는 반사실적(counterfactual) 실험이지, slot 27이 지금도
> 실패 중이라는 뜻이 아닙니다.

| | 판매 문장(정답) | 삭제 문장(A5 one-shot 당시 실제로 선택됨) |
|---|---:|---:|
| 겹침비율 | **0.11** | **0.78** |

원인 두 가지가 겹쳤습니다.
1. 상품명("2026 아라드 패스 차원의 별자리 아바타 콤보 상자")이 길고, **오답
   문장만 이 상품명을 그대로 반복**해서 겹침 점수가 커집니다.
2. 정답 문장은 "판매"라는 단어를 아예 안 쓰고 "~점검 후부터 ~점검 전까지
   ... 만나보실 수 있습니다"라는 **관용구**를 씁니다 — 상품명 토큰을 빼고
   다시 계산해봐도 정답·오답 둘 다 겹침 0이 나와서(직접 확인), 상품명을
   빼는 정도로는 못 고칩니다. 이건 어휘 겹침이 아니라 관용구를 아는지의
   문제라 이 검사로 해결할 문제가 아닙니다.

**이 검사를 evidence 선택(어떤 문장을 근거로 채택할지) 단계에 그대로
적용하면 slot27류 사례를 오히려 악화시킵니다.**

## 3. 적용 범위 (반드시 좁힐 것)

**Q1/Q2 커버리지 계약의 2차 안전장치로만 적용**하고, evidence 선택/재랭킹
단계에는 적용하지 않습니다.

```
적용 위치: question_coverage_contract가 "accepted"로 판정한 각 claim에 대해,
          question_ref 텍스트와 cited evidence_ref 텍스트의 겹침비율을 추가로 계산
조건:     겹침비율이 매우 낮으면(예: 0.0, 즉 유의미한 겹침 토큰이 하나도 없으면)
          Qwen이 accepted로 판정했더라도 서버가 이를 재검토 대상으로 표시
동작:     자동으로 unsupported 처리하지 말고, 우선은 진단 신호(로그/verification
          필드)로만 노출 — false positive(정상인데 겹침이 우연히 낮은 경우, 예:
          동의어·관용구 정답)가 있을 수 있으므로 자동 차단은 다음 라운드에 결정
```

적용 안 하는 곳:
```
- select_semantic_product_evidence_units / evidence pack 구성 단계
- 절별(clause-level) top-1 재랭킹
- 그 외 slot27류(같은 주어를 공유하는 여러 후보 중 관계어로 구분해야 하는) 문제
```

## 4. 검증표 (재현 필수)

```
slot12 Q2: q="정확한 연령 확인 절차를 알려줘"
           ev="이벤트와 관련된 개인정보 수집 및 이용 동의, ... 동의 거절 시 사전예약이 불가합니다."
           → overlap_ratio == 0.0 (겹침 토큰 0개)

slot4 Q2 원래 실패: q="특별 할인 쿠폰 금액을 알려줘"
           ev="데일리샷 신규 회원 가입 시 현금처럼 사용 가능한 3,000 포인트를 제공합니다."
           → overlap_ratio == 0.0

slot12 Q1(정답, 회귀 방지): q="...14세 미만 계정이 참여할 수 있었는지"
           ev="- 단, 14세 미만 계정은 참여할 수 없습니다."
           → overlap_ratio >= 0.4 (낮은-겹침 신호로 오탐되면 안 됨)

slot27 sale_period(이 검사를 evidence 선택에 적용하면 안 되는 이유를 보여주는
           반사실적 실험 — slot27 자체는 Kiwi 수정 이후 지금 정상 통과함):
           정답 문장 겹침(0.11)이 A5 one-shot 당시 실제 선택됐던 삭제 문장
           겹침(0.78)보다 낮다는 것을 재확인 — 이 검사를 evidence 선택 단계에
           넣지 않았다는 증거로 남길 것.
```

## 5. 하지 말 것

- 이 겹침 검사를 evidence pack 구성/재랭킹 단계에 넣지 않는다 (slot27류 역효과
  직접 확인됨).
- 낮은 겹침을 즉시 자동 차단으로 연결하지 않는다 — 먼저 진단 신호로만 노출해
  false positive 비율을 관찰한다.
- 새 토크나이저나 형태소 분석기를 도입하지 않는다 — 기존 `_compact_tokens`
  재사용으로 충분함을 확인했다.
- 이 검사 하나로 "semantic entailment 문제가 해결됐다"고 결론 내지 않는다 —
  slot4/12류의 일부만 잡고, slot27류는 못 잡는다는 것을 명확히 구분해서
  기록한다.
