## 2. 봉인 (freeze)

승인된 64문항을 **내용주소 불변 산출물**로 동결하세요.

- 파일명에 SHA256 포함, `write_immutable`로 재기록 방지.
- 봉인 매니페스트에 다음을 남길 것:
  - 원본 candidate SHA, 봉인 SHA, 코퍼스 SHA(`bd0242b3…`), 감수자·시각
  - `sealed_scoring_allowed: true`, 이후 `execution_allowed: true`
  - 8×8 구성(출처 8 × 유형 8), 정직보류 8건, 좌표 90건
- 봉인 이후에는 **질문·정답·근거를 절대 수정 금지.** 수정이 필요하면 새 세트로.

## 3. 단 1회 실행 (one-shot)

봉인된 64문항에 대해 typed evidence-ref 파이프라인을 **정확히 한 번** 실행.

```

생성: typed evidence-ref (모델은 E-ref 선택, 서버가 원문 좌표로 조립)

모델: qwen3-8b:ctx8192
```

- 결과를 보고 **코드·프롬프트·검색을 바꾼 뒤 재실행하면 안 됨.** 그 순간 이 세트는
  adaptive로 오염되어 홀드아웃 자격을 잃습니다. 봉인 카나리 규율과 동일.
- 실행 산출물(케이스 jsonl + 요약 json)을 내용주소로 동결.

## 4. ★ 채점 — 자기채점 금지가 이 라운드의 핵심

adaptive-32에서 자동 literal 25/32 → 사람 재판정 30/32였습니다. 그 +5는 사람이
"06시 ≡ 6시", "표 행 ≡ 자연어 gold" 같은 **동등 표현**을 손으로 정답 처리한 것입니다.
홀드아웃에서 이 방식을 쓰면 **정직한 측정이 아닙니다.**

이번엔 다음을 지키세요.

**(a) 정규화를 채점기에 내장** — 사람이 손대던 동등성을 코드가 처리:
- 시각: `06시` ≡ `6시` ≡ `06:00`, 날짜: `08월 13일` ≡ `8월 13일`
- 금액: `4,000만 골드` ≡ `40,000,000 골드`
- 표 행 인용 ≡ 자연어 gold (값이 같으면 인용 형태 무관)
- 이 정규화 규칙은 **실행 전에 확정**하고 매니페스트에 명시. 실행 후 결과를 보고
  규칙을 추가하면 그것도 자기채점입니다.

**(b) 두 지표를 고정 분모로 보고:**
- 값 정확도 `gold_value_complete`: 답변에 gold 값이 다 있나 (정규화 후)
- 인용 커버리지 `all_evidence_spans_hit`
- 분모 = gold 값이 있는 문항 전체. `정답 / 오답 / 무응답(보류)`을 각각 세서 보고.
  "답한 것 중 맞은 비율"만 내면 덜 답하는 쪽이 유리해 보이는 착시가 생깁니다.

**(c) 정직한 보류 8문항 별도 집계:**
- unsupported 요구를 모델이 **보류했나(정답)** vs **지어냈나(false-full)**.
- 이 8건의 false-full = 0이 이 프로젝트의 핵심 주장이므로 따로 찍을 것.

**(d) 사람 재판정이 정말 필요한 잔여 케이스가 있으면**, 자동 점수를 **먼저 고정**하고,
그 위에 "사람 판정으로 N건 추가 인정"을 **분리해서** 보고. 자동 숫자를 사람 판정으로
덮어쓰지 말 것. 헤드라인은 자동 숫자입니다.

## 5. 판정 게이트 (실행 전 등록)

```
[필수] generation_error = 0
[필수] 정직한 보류 8문항 false-full = 0
[주지표] 값 정확도(자동, 정규화 후) 를 그대로 보고 — 목표치를 사후에 낮추지 말 것
[참고] 인용 커버리지, 보류율
```

- false-full > 0 이면 홀드아웃에서 실패한 것이며, 그 케이스를 원인 분석 대상으로.
- 자동 값 정확도가 기대(adaptive의 사람판정 30/32)보다 낮게 나와도 **그게 진짜 숫자**입니다.
  낮으면 낮은 대로 보고. 이 세트의 목적은 "높은 수"가 아니라 "정직한 일반화 수"입니다.

## 7. 이 라운드가 프로젝트에서 갖는 의미

지금까지 좋은 숫자(adaptive 30/32)는 전부 **반복 개발에 쓴 세트 + 사람 재판정**이었습니다.
이 64문항은 **개발에 한 번도 안 쓴 독립 세트**이고, 자기채점을 배제한 자동 숫자입니다.
그래서 이 결과가 **처음으로 "일반화 성능"이라 부를 수 있는 숫자**가 됩니다.
숫자가 높든 낮든, 정직하게 나온 그 값이 포트폴리오의 핵심 근거입니다.
