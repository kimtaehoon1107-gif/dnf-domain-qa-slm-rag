## 0. 정정 — A6-2와 A6-22는 같은 유형이 아닙니다 (Claude 오류)

제가 이전 지시서에서 두 슬롯을 "문서 메타데이터 오인" 한 그룹으로 묶었습니다.
**원본 청크를 열어보니 틀렸습니다.**

### A6-2 — 진짜 메타데이터 오염 ✅

```
### 공지사항
퍼스트서버
8월 12일 퍼스트서버 초기화 및 점검 안내
2025.08.12 14:00          ← 게시 타임스탬프 (본문 아님)
37,477                    ← 조회수 (본문 아님)
안녕하세요. 던전앤파이터 퍼섭지기입니다.
8월 12일 15시부터 퍼스트 서버 초기화 및 점검이 진행될 예정   ← 실제 정답
퍼스트서버 오픈 일정은 8월 13일(수)입니다.                  ← 실제 정답
```

**게시 타임스탬프와 조회수가 청크 본문 텍스트에 그대로 들어 있습니다.**
모델이 `2025.08.12 14:00`을 점검 시작 시각으로 답했고(relevance 0.981),
verifier의 `factual_values_supported`는 근거에 `14:00`이 실제로 있으므로
**통과시켰습니다.**

### A6-22 — 메타데이터가 아니었습니다 ❌

```
# 모험가님! 꼭 알아두세요.
당첨 세라는 12/9(화) 오전 중 참여 계정에 충전해드릴 예정입니다.
# 버그 제보, 이렇게 조치했습니다.
모든 버그 제보는 담당부서에서 100% 확인 하여 …
게임 플레이에 영향을 주는 버그는 우선순위를 높여 대부분 12/4(목) 업데이트에 맞추어 최대한 수정하였습니다.
                                                    ↑ 본문에 실재하는 텍스트
```

**`12/4(목)`은 게시일이 아니라 본문에 실제로 있는 문장입니다.**
"업데이트 날짜"를 "답변 기한"으로 잘못 연결한 것이며, 이건 A6-1과 같은
**대상·관계 오연결**입니다.

`published_at`이 2025-12-04인 것은 우연의 일치입니다. 제가 그것만 보고
메타데이터 오염이라고 단정했습니다.

### 재분류 (확정)

```
A6-2   → 헤더 메타데이터 오염       ← 이 지시서의 유일한 대상
A6-22  → 대상·관계 오연결 그룹으로 이동 (A6-1과 함께)
```

**이 라운드는 A6-2 한 건만 다룹니다.** 범위가 줄어든 것이 정상입니다.

  dnf_notice      396

  dnf_monthly_item 13

```

### 구조가 매우 규칙적입니다

```
[0] ### 공지사항          섹션 헤딩
[1] 점검 / 일반           카테고리
[2] 9/18(목) 정기점검 안내  제목
[3] 2025.09.16 17:30      게시 타임스탬프   ← 제거 대상

타임스탬프 줄 위치 분포: **3번째 줄 414건 / 4번째 줄 86건 / 2번째 줄 2건**
→ 502건 중 500건이 2~4번째 줄. 기계적으로 특정 가능합니다.

## 2. 왜 이게 중요한가 — verifier를 무력화합니다

```
[A6-2] 모델 답변 "점검은 14시에 시작한다"
       verifier factual_values_supported → 근거에 14:00 존재 → 통과 ✅
       실제 본문은 15시. 오답.
```

**근거에 문서 메타데이터가 있으면 숫자·시각·날짜 검증이 그것으로 충족됩니다.**
verifier가 정상 작동한 상태로 오답을 통과시킵니다.

조회수(`55,915`, `37,477`)도 같은 위험을 갖습니다. 숫자를 묻는 질문에서
근거 안의 조회수가 검증을 통과시킬 수 있습니다.

## 3. 🔒 코퍼스 재빌드 금지

```
chunk_id = sha256(parent_document_id, offset_source, start_offset, end_offset,
                  sha256(display_text), chunker_version)
```

`display_text`를 바꾸면 **chunk_id가 전부 바뀝니다.** 그러면
A6·A5·sealed64·existing32·new_claim32의 **모든 골드 좌표가 무효화**되고,
지금까지의 평가 결과가 재현 불가능해집니다.

**절대 코퍼스를 다시 만들지 마십시오.** 런타임 필터로만 처리합니다.

## 4. 요구사항 — atomic evidence unit 생성 시 헤더 라인 제외

### 안전성 확인 (Claude 사전 측정)

```
A6 골드 근거 단위 총 62건 / 헤더 영역과 겹침 0건
```

**골드 근거가 헤더 영역에 사는 경우는 없습니다.** 제외해도 정답 근거를
잃지 않습니다.

### 구현 방향

청크의 `display_text`에서 **문서 헤더 블록**을 식별하고, 그 범위에 속하는
atomic evidence unit을 후보에서 제외하십시오.

```
헤더 블록 판정 (구조로만, 도메인 어휘 금지):
  - 청크 시작부 6줄 이내
  - 그리고 다음 중 하나
      · 게시 타임스탬프 형태          YYYY.MM.DD HH:MM
      · 조회수 형태의 단독 숫자 줄     1,234 / 55,915  (다른 텍스트 없이 숫자만)
  - 본문 첫 문장이 시작된 뒤에는 적용하지 않음
```

- `display_text`와 `chunk_id`는 **바꾸지 마십시오.**
- offset 좌표계도 그대로 유지하십시오. **해당 offset 범위의 unit을 후보에서
  빼는 것뿐입니다.**
- 인용 복원은 기존과 동일하게 동작해야 합니다.

### 하지 말 것

- 청크 텍스트를 재작성하지 마십시오.
- 문서 제목 줄(`[2]`)은 제거하지 마십시오. **제목은 대상 식별에 쓰입니다.**
- 본문 안의 날짜·시각(`8월 12일 15시`, `12/4(목)`)을 건드리지 마십시오.
  **본문 사실입니다.**
- 카테고리 줄(`점검`, `일반`)은 이번 범위 밖입니다. 건드리지 마십시오.
- 다른 가드(`_cross_parent_*`, `_normative_relation_supported`, 채점기)를
  건드리지 마십시오.

## 5. 회귀 케이스

| # | 케이스 | 기대 |
|---|---|---|
| 1 | A6-2 | `2025.08.12 14:00`이 pack에서 사라지고, 본문 `15시`가 선택됨 |
| 2 | A6-2 | 최종 답변 시작 시각이 **15시**로 변경 |
| 3 | 골드 62건 (A6 전체) | pack 진입 여부 **불변** |
| 4 | 본문에 시각이 있는 공지 (합성) | 본문 시각은 **그대로 선택됨** |

| 6 | 인용 좌표 복원 | 전건 **바이트 일치 유지** |

**3번과 5번이 핵심입니다.** 이 수정은 대부분의 문항에서 아무것도 바꾸면
안 됩니다.

## 9. 이 라운드 이후 남는 것

```
그룹  대상·관계 오연결      A6-1 · A6-22        ← 가장 어려움. Typed verifier 유혹 주의
그룹  evidence pack 선택   A6-4                ← 고아 목록 처리 전례 있음
그룹  검색·후보 조립        A6-22               ← 지연 예산 확인 후
그룹  표 원자화 왜곡        A6-7                ← 빌드 타임, 런타임 무관
```

**A6-22가 두 그룹에 있습니다.** 고객센터 근거가 후보에 없는 문제(검색)와
업데이트 날짜를 기한으로 연결한 문제(관계)가 겹쳐 있습니다.

다음 라운드 후보로는 **A6-7 표 원자화**를 권합니다 — 빌드 타임 결함이고,
런타임을 안 건드리고, 검증이 원자화 산출물 비교로 끝납니다.

```
현재 A6-7 근거:
  "| [타이드 바운드] …기본 쿨타임 12초로 변경… | [타이드 바운드] …기본 쿨타임 9초 로 변경… |"
  표 헤더: | 변경 전 | 변경 후 |

골드: 타이드 바운드 20→18초 / 질풍 개화 12→9초
→ 이 행은 12→9를 타이드 바운드라고 말합니다. 근거 자체가 틀렸습니다.
→ 모델이 이걸 그대로 답한 것은 근거에 충실한 결과이며 생성 오류가 아닙니다.
```
