```
질문   게임에서 버그를 발견하면 어디에 제보해야 하고, …기한은 정확히 며칠이야?
정답   [2-2-6] 고객은 버그 발생 시 고객센터를 통해 회사에 제보해야 합니다.
```

7개가 **제목에 "버그 제보"**를 그대로 갖고 있습니다. 정답 청크는 제목이
`던전앤파이터 운영정책`, heading이 `['운영정책']`뿐이라 질문 어휘와의
연결고리가 본문 한 줄에만 있습니다.

### 구조적 의심

```
"버그"+"제보" 동시 포함 청크    144건
   dnf_account_policy  123건   ← 전부 heading ['운영정책'], 각 1,700자 안팎
   dnf_notice           21건   ← 제목부터 서로 다름
```

**운영정책은 하나의 긴 문서가 123개 대형 청크로 쪼개져 있고 전부 같은
heading을 갖습니다.** 정책 관련 질문 전체가 같은 불리함을 안고 있을 수
있습니다.

**이 진단의 목적은 그게 slot 22 한 건인지 계열 전체인지 확인하는 것입니다.**

## 2. 측정 설계

### 공통 조건

```
대상   A6 32문항 전체 (성공·실패 모두. 성공 문항이 대조군)
런타임 현행 그대로 (헤더 필터·R1·R2 적용 상태)
깊이   BM25·BGE 각각 top-200 까지 확장해 순위를 찾는다
       ※ 이건 측정용 확장이며 런타임 기본값을 바꾸는 게 아님
Qwen   0회
```

### D1 — 골드 청크 순위

각 문항의 각 요구에 대해, `acceptable_evidence_units`의 `chunk_id`를 골드로
보고 다음을 기록하십시오.

```
bm25_rank            BM25 top-200 내 순위 (없으면 null)
dense_rank           BGE-M3 top-200 내 순위 (없으면 null)
hybrid_union_rank    union 후 순위
in_hybrid_union      현행 깊이(20) 안에 들어왔는가
reranker_rank        리랭커 통과 후 순위 (union에 있었을 때만)
in_final_candidates  최종 8개 후보에 들어왔는가
```

**골드가 top-200에도 없으면 `null`로 기록하고 그 사실을 강조하십시오.**
그게 깊이 확대가 통하지 않는다는 뜻입니다.

### D2 — 출처별 집계

```
source_id 별로
   문항 수 / 골드가 union에 든 비율 / 골드가 최종 후보에 든 비율
   골드 순위 중앙값
```

특히 `dnf_account_policy`와 나머지를 비교하십시오.

### D3 — 청크 크기 상관

```
골드 청크의 display_text 길이 대 골드 순위
골드 문장(evidence unit) 길이 / 골드 청크 길이 = 신호 비율
```

**가설**: 청크가 클수록, 그리고 정답 문장이 청크에서 차지하는 비율이
작을수록 순위가 낮다.

### D4 — 최종 후보의 출처 분포

```
문항별 최종 후보 8개의 source_id 분포
정답 출처가 최종 후보에 0개인 문항 목록
```

slot 22처럼 **정답 출처가 아예 없는 문항이 몇 개인지**가 B안(출처 다양성
보장)의 근거가 됩니다.

```
  → 전건 스캔으로 다른 문항 악화 확인 필수

  → 문장 단위 검색. 인덱스 구조 변경이라 큰 작업
  → 이번 로드맵에서는 착수하지 말고 포트폴리오에 "규명된 한계"로 기록

  → 검색이 고쳐져도 요구 2는 여전히 unsupported를 선언해야 하고,
     8B 모델은 그걸 안 한다는 것이 이미 확인됨 (계약 재평가 NO-GO)
```

## 8. 이 진단의 가치

수정으로 이어지지 않아도 **포트폴리오에 쓸 결론이 나옵니다.**

```
"정답 문장은 질문과 거의 완벽하게 대응한다.
   질문: 게임에서 버그를 발견하면 어디에 제보해야 하고
   정답: 고객은 버그 발생 시 고객센터를 통해 회사에 제보해야 합니다

 그런데 이 문장은 1,703자 청크의 3.5%였고, 검색은 청크 단위이며,
 원자화는 검색 다음에 일어난다. 따라서 정답 문장은 경쟁할 기회조차 얻지 못했다.

 이것은 모델의 실패가 아니라 인덱싱 입도의 문제다."
```

**A6 20/32의 남은 실패 12건 중 몇 건이 같은 원인인지 수치로 말할 수 있게
됩니다.** 그게 이 진단의 주 산출물입니다.
