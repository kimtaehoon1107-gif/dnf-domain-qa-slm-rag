## 1. 남은 단 하나의 레버

계약이 claim을 쪼갰는데도 두 claim 모두 `E1`을 참조했습니다.
**모델이 E3를 선택지로 보지 않습니다.** 이유는 랭킹입니다.

```python
# src/v3/product_evidence_pack.py:1095
for query in selection_queries:
    for index in ranked_indexes(query)[:reserve_per_query]:
        ...
        question_focus_by_unit[id(unit)] = query   ← 먼저 선택한 query가 라벨
```

E1이 첫 절 랭킹 **0.992로 1위**라 첫 절 라벨을 받고 E1 자리에 놓입니다.
모델 입장에서는 서버가 "이게 첫 절의 답"이라고 표시해준 것입니다.

### 랭킹이 도입문을 못 봅니다 — 의도된 설계였습니다

R2는 도입문을 **Qwen 문맥에만** 넣고 **랭킹에서는 제외**했습니다.

```python
# src/v3/product_evidence_pack.py:54
def _ranking_context_text(unit):
    context = str(unit.get("context_text") or "")
    start = context.find(_TABLE_INTRODUCER_MARKER)
    if start < 0:
        return context
    subject_start = context.find(_TABLE_SUBJECT_MARKER, start)
    if subject_start < 0:
        return context[:start]          ← "표 도입:" 이후를 잘라냄
    return context[:start] + context[subject_start:]
```

리랭커가 실제로 채점하는 문자열은 이렇습니다.

```python
# _atomic_reranker_text() (line 989)
제목: {title}
문맥: {_ranking_context_text(unit)}     ← 도입문이 제거된 문맥
근거: {text}
```

**도입문이 "질풍 개화 옵션"이라고 말해도 랭킹은 그걸 못 봅니다.**
랭킹은 `| [타이드 바운드] … 12초 … | … 9초 … |`만 보고 첫 절에 1위를 줍니다.

## 2. 왜 지금 재평가하는가

R2 라운드에서 도입문을 랭킹에 넣는 **점수 결합안이 기각**됐습니다.

```
점수 결합안: pack 변경 246/1,300 → "악화 위험 확인" → 폐기
ranking 분리안 채택 (pack·순서 변경 0)
```

**그 판정은 `value_present`가 만들어지기 전에 내려졌습니다.**

```
표 바인딩 라운드   246/1,300 측정 → "악화 위험"     ← 판정 지표 없음
      ↓
값 존재 지표 도입  value_present 생성
      ↓
지금               246건이 개선인지 악화인지 판정 가능
```

당시엔 **"pack이 246건 바뀐다"는 사실만 알았지, 그 변화가 좋은지 나쁜지
알 수 없었습니다.** 요구별 예약 재평가와 정확히 같은 상황입니다.

> 기각을 번복하자는 게 아닙니다. **당시 측정 불가능했던 것을 이제 측정
> 하겠다는 것입니다.** 보고서에 이 구분을 명시하십시오.
