# 지시서 — 값 존재 지표 교체 + 괄호 값 결합 진단

작성: 2026-08-05 · 대상: Codex
성격: **M단계는 측정기 교체, P단계는 진단. 런타임 적용은 이 문서 범위 밖.**
선행: 표 주어 바인딩 라운드 NO-GO / 롤백 완료

---

## 0. 정정 — `55/62 visible` 기준은 제가 넣은 것이고, 결함이 있습니다

제가 [헤더 메타데이터 지시서](product_free_rag_header_metadata_contamination.md)와
[표 바인딩 지시서](product_free_rag_table_subject_binding.md) 양쪽에
`A6 골드 62건 진입 벡터 불변 (55/62)`을 통과 기준으로 넣었습니다.

**이 지표는 겹침(overlap) 기준이라 정답 값의 존재를 보장하지 않습니다.**

```
A6-7 골드 좌표   191-224  '타이드 바운드 - 쿨타임이 감소합니다. (20초 → 18초)'
실제 pack unit   189-212  '- 타이드 바운드 - 쿨타임이 감소합니다.'

→ 191~212에서 겹침 → "visible" 판정 ✅
→ 그런데 그 unit에 20초도 18초도 없음 ❌
```

**표 바인딩 라운드가 그 증거입니다.** `55/62 유지`를 통과했는데 A6-7은
실패했습니다. 측정기가 실패를 잡지 못했습니다.

### 정확한 영향 범위

| 용도 | 유효성 |
|---|---|
| "before == after 불변" 회귀 탐지 | ⚠️ 부분 유효 — 같은 잣대로 전후 비교 |
| "정답 근거가 pack에 들어왔다" 주장 | ❌ **무효** |

지난 두 라운드의 "골드 불변" 판정 자체가 뒤집히지는 않습니다. 다만 악화
탐지 감도가 낮았습니다.

**M단계를 먼저 하는 이유**: 지금 지표로는 P단계 수정의 성공/실패를 판정할 수
없습니다. 수정 전에도 55/62, 수정 후에도 55/62가 나옵니다. 겹침은 어차피
있으니까요.

# M단계 — 값 존재 지표(value_present) 도입

## M1. 지표 정의

```
현행  gold_span ∩ pack_unit_span ≠ ∅                    → visible
신규  requirement.required_values 의 각 값이
      그 요구에 배정된 pack unit 텍스트에 실제로 존재    → value_present
```

요구 단위로 판정하고, 슬롯 단위로도 집계하십시오.

```
value_present_full     요구의 required_values 전부가 pack에 존재
value_present_partial  일부만 존재
value_present_none     하나도 없음
```

## M2. ⚠️ 표면 문자열 비교로 만들지 마십시오

A6 자동 채점이 **12건을 오판**한 원인이 정확히 그것입니다.

```
'2025-09-11 점검 후'  vs  '25.09.11 점검 후'      날짜 축약
'숫자 6자리'          vs  '6자리 숫자'            어순
'264칸'               vs  '264 칸'                공백 1
'2,000만 골드'         vs  '2000만 골드'           쉼표 1
```

**`src/v3/value_normalization.py`를 재사용하십시오.** 숫자·날짜·시각·불리언·
통화는 정규화 후 비교합니다. `번 → 회` 정규화도 이미 여기 계열에 있습니다.

정규화로도 안 되는 서술형 값(`'홈페이지 > 서비스센터 > 보안 > 간편잠금'`)은
**토큰 포함 비율**로 판정하고, 그 임계값을 보고서에 명시하십시오.

불리언 골드(`[false]`, `[true]`)는 값 문자열이 아니라 **의미 판정**이
필요하므로, 이번 지표에서는 **별도 분류로 분리**하고 합산하지 마십시오.

## M3. A6 62건 새 기준선 산출

```
방법: retrieval-only shadow 실행 (Qwen 호출 0회)
      A6 32문항의 evidence pack을 다시 구성하고 value_present 계산
      런타임 코드 변경 없음
```

A6 one-shot은 W0-1 이전이라 `evidence_pack`이 저장돼 있지 않습니다.
저장 candidate로 재구성하거나 retrieval만 다시 도십시오. **Qwen은 절대
부르지 마십시오.**

### 판정 (사전 등록)

```
□ 새 기준선 값을 그대로 기록한다. 55보다 낮게 나올 것으로 예상하지만,
  예상치를 목표로 삼지 말 것.
□ value_present=false 인데 overlap=true 인 요구를 전부 목록화한다.
  ← 현행 지표가 놓치고 있던 것들. 이게 이번 M단계의 핵심 산출물.
□ 그 목록에서 원인을 분류한다 (괄호 분리 / 표 분리 / 그 외).
```

## M4. 이후 통과 기준 대체

M단계 완료 후, **이후 모든 라운드의 통과 기준에서 `overlap visible`을
`value_present`로 교체**하십시오. 두 지표를 함께 보고해도 되지만, **판정
기준은 `value_present`입니다.**

# P단계 — 괄호 값 결합 진단

## P1. 문제

```
원문   '- 타이드 바운드 - 쿨타임이 감소합니다. (20초 → 18초)'

분할   [189-212] '- 타이드 바운드 - 쿨타임이 감소합니다.'   ← 숫자 없음
       [213-224] '(20초 → 18초)'                          ← 정답, 주어 없는 고아
```

`_sentence_spans()`가 마침표에서 자르면서 정답 숫자가 주어 없는 단편이
됩니다. 그 단편에는 대상어가 없어 relevance가 낮고 E1~E8에서 탈락합니다.

**A6-7의 첫 절이 틀린 직접 원인입니다.** 표 바인딩으로는 고칠 수 없습니다.

## P2. 범위 (Claude 개략 측정 — 정밀 재측정 필요)

```
전체 문장 unit (표·헤딩 제외)   47,425
숫자 포함 고아 단편              약 96건  (0.20%)

출처별  account_policy 33 · event 20 · game_guide 14 · faq 10
        seria_shop 9 · notice 9 · update 1
```

**이 96은 제 거친 휴리스틱입니다**(`앞 조각 있음 + 숫자 포함 + 30자 이하 +
서술어 없음`). Codex가 정밀 기준으로 다시 뽑으십시오.

**모집단이 작다는 게 이 라운드의 장점입니다.** 이 프로젝트는 소수 프로브에
두 번 데었는데, 이번엔 반대로 **전수를 사람이 볼 수 있는** 드문 경우입니다.

## P3. 진단 단계

### P3-1. 전수 추출 (Qwen 0회)

고아 단편 후보를 전부 뽑아 다음을 기록하십시오.

```
source_id / chunk_id / 앞 조각 텍스트 / 분리된 단편 텍스트 / 좌표
단편 유형 분류:
   괄호형        (20초 → 18초)
   화살표형      20초 → 18초
   기호 접두형   ※ …, ▶ …
   단독 숫자형   115
   그 외
```

### P3-2. 사람 전수 검토 🔴

**추출된 전건을 사람이 확인**하고 다음을 판정하십시오.

```
결합해야 함    앞 문장의 값이며 분리되면 의미를 잃음
결합하면 안 됨 독립된 별개 사실이거나 앞 문장과 무관
애매함        판단 보류
```

**여기서 규칙을 먼저 만들지 마십시오.** 데이터를 보고 나서 만듭니다.
지난 라운드들에서 규칙을 먼저 세우고 데이터를 맞춘 실수를 반복하지 마십시오.

### P3-3. 규칙 설계

사람 검토 결과에서 **구조적 조건만으로** 결합 규칙을 도출하십시오.

```
후보 신호 (예시일 뿐, 이대로 구현하라는 뜻 아님):
  · 단편이 여는 괄호로 시작하고 닫는 괄호로 끝남
  · 단편에 서술어가 없음
  · 단편 길이 상한
  · 앞 조각과 같은 줄에 있음        ← 줄 경계를 넘지 말 것
```

**금지**: 스킬명·아이템명·문서명 허용목록, 숫자 값 자체에 대한 조건.

### P3-4. shadow 적용 + value_present 판정 (Qwen 0회)

런타임을 바꾸지 말고 진단 스크립트 안에서만 결합안을 적용해 비교하십시오.

```
비교 대상
  A6 62 요구의 value_present  (M3 기준선 대비)
  pack 진입 unit 집합 변화
  단계별 지연 (특히 candidate_rerank)
```

### 판정 (사전 등록)

| 게이트 | 기준 |
|---|---|
| A6-7 `base_cooldown_change` | `20초`·`18초` **둘 다** value_present |
| M3 기준선 대비 | value_present **감소 0건** |
| pack 집합 | 변경된 record 전부 목록 보고 |
| 지연 | 증가분 수치 기록 (판정 기준 아님) |

**`value_present`가 1건이라도 줄면 실패입니다.** 결합이 다른 unit을 밀어낼
수 있습니다.

## 이후 순서 (이 문서 범위 밖)

```
1. M단계 완료 → 이후 모든 통과 기준을 value_present로 교체
2. P단계 통과 → 괄호 값 결합 런타임 적용 (별도 라운드)
3. 표 주어 바인딩 재적용 → A6-7 두 절 모두 검증
4. A6-4  evidence pack 선택
5. A6-22 검색·후보 조립 (지연 예산 확인 후)
6. A6-1 · A6-22 대상·관계 역할
7. tail 지연 원인 (hook OFF에서도 p95 101초, W0-2 계측으로 특정 가능)
8. frozen manifest 테스트 2건 정리
```

**3번에서 A6-7의 두 절이 모두 맞아야 이 계열이 끝납니다.** 첫 절은 괄호
결합으로, 둘째 절은 표 주어 바인딩으로 각각 다른 수정이 필요합니다.
