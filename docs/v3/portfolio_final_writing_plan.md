## 0. 이 라운드의 성격

파이프라인·평가·데이터를 **일절 건드리지 않는다.** 이미 측정된 결과를
읽는 사람이 이해할 수 있는 형태로 옮기는 작업이다.

가장 큰 위험은 **숫자 창작**이다. 이 프로젝트의 정체성은 "정직한 측정"이라,
포트폴리오에 근거 없는 숫자가 한 줄이라도 들어가면 프로젝트 주장 전체가
무너진다. §3의 확정 숫자표를 벗어난 수치는 **artifact 경로를 함께 제시하지
않으면 쓸 수 없다.**

## 1. 확정된 설계 (변경 금지)

### 1-1. 구조 — 3막

방향을 두 번 틀었고, **틀 때마다 측정이 근거였다.** 이게 이 문서의 서사다.

```

2막  v3      생성을 타입 계약으로 묶자
             → 37/64. 96개 요구 중 계약은 22개. 실사용 불가.

3막  Product 계약을 버리고 자유 생성 + 인용 검증으로
             → 20/32. 현재 시스템.
```

### 1-2. 헤드라인

**`37/64`와 `20/32`를 병기한다.** 단, 다음을 반드시 명시한다.

> 두 숫자는 **다른 벤치마크·다른 시스템**이다. 64문항 세트와 32문항 세트는
> 문항이 겹치지 않으며 난이도도 통제되지 않았다. **어느 쪽이 더 낫다는
> 비교를 하지 않는다.**

`20/32`가 `37/64`보다 백분율이 높다는 식의 문장을 쓰면 실패.

### 1-3. 1막 분량

**1~2쪽으로 압축.** v1/v2의 데이터 구축·RAFT·누수 검사 세부는 넣지 않는다.
넣을 것은 **"왜 SLM 파인튜닝을 접었는가"** 하나다.
상세는 기존 `PORTFOLIO_REPORT.md` 링크로 넘긴다.

### 1. 문제 정의

게임 공식문서 QA가 왜 어려운지 **구체 사례로** 보인다. 추상적 서술 금지.

- 같은 스킬의 쿨타임이 조건에 따라 두 개 (A6-7 원문 인용)
- 이벤트 기간이 지나면 답이 달라짐
- 표의 셀 안 표기와 표의 주어가 다름

### 2. 세 번의 방향 전환

각 전환마다 **무엇을 측정했고 그래서 뭘 접었는지** 한 문단씩.
"더 좋은 방법을 찾았다"가 아니라 "측정 결과가 이랬다"로 쓴다.

### 3. 1막 — v1/v2 (1~2쪽)

넣을 것: 목표, RAG-only vs tuned 비교 결과, **blind를 열지 않기로 한 판단과 이유**.
빼는 것: 데이터 스키마, RAFT 구성, 누수 검사 세부, LoRA 하이퍼파라미터.
말미에 `PORTFOLIO_REPORT.md` 링크.

### 4. 2막 — v3 typed

넣을 것: typed value + evidence_ref 구조, 검증 5단계, `37/64`(sealed 라벨),
**승격하지 않은 이유**(96개 중 계약 22개 등).
`PORTFOLIO_V3_DRAFT.md` 내용을 압축하되 **숫자는 §3-B 절차로 재확인 후** 옮긴다.

### 5. 3막 — Product Free RAG (전부 신규)

**5-1 파이프라인**

```
질문 → 절 분해 → BM25 + BGE-M3 hybrid → BGE reranker
     → atomic evidence pack → Qwen3 8B → 인용 좌표 검증 → 렌더
```

각 단계에서 실제로 쓰는 파라미터를 코드에서 확인해 적는다
(dense weight, top-k, 청크당 개수 등). **기억이 아니라 코드 확인.**

**5-2 봉인 평가 규율**

```
계약 작성 → 사람 감수 → SHA 동결 → 1회 실행 → 재실행 영구 금지
```

SHA 2개를 실제로 적는다. adaptive replay가 왜 공식이 아닌지 설명한다.

**5-3 결과 — 40%p 격차**

이 절의 핵심은 **자동 21.9% → 사람 62.5%** 다.

- 자동 채점기가 무엇을 놓쳤는지 사례 1~2건
- 사람 감수가 **모델에 유리하게만** 작동하지 않았음을 보일 것
  (slot 6에서는 gold 자체의 오류를 찾아냈고, 봉인셋을 고치지 않고
   overlay로 기록했다 — 이게 규율의 증거다)

### 6. 실패 분석 — 본편

**6-1 실패 귀속 체계**

```
S1 검색 실패 / S2 pack 선택 / S3 생성 / S4 verifier 과차단 / S5 관계 오연결
```

**6-2 A6-7 심층 — 이 절이 문서에서 가장 길어도 된다**

순서:

1. 문서 원문 그대로 (브레이커 항목 + 표 2개)
2. 정답이 왜 두 개인지 — 평시 20→18, 질풍 개화 시 12→9
3. 모델이 받은 JSON (evidence_units의 `context`에 `표 도입: '질풍' …`이
   **이미 들어 있었다**는 사실이 핵심)
4. 결정적 증거 — **같은 근거 유닛 하나가 질문 주어에 따라 두 주어로 결속**

   ```
   "타이드 바운드 …?"      → F1E1을 타이드 바운드에 결속
   "질풍 개화 옵션 …?"     → 동일 유닛 F2E1을 질풍에 결속
   ```
5. 이건 환각이 아니라 **조건 탈락** — 문서에 있는 숫자에서 조건만 사라짐
6. 6번의 시도와 전부 실패한 이유 표

   | 시도 | 겨냥 | 결과 |
   |---|---|---|
   | 표 주어 결속 | 도입부를 context에 | 이미 들어 있었음 |
   | ranking context | 도입부를 랭킹에도 | 이미 들어 있었음 |
   | 절 분해 (F0) | 질문 분리 | 분리됨, 부작용으로 롤백 |
   | 요구별 예약 | 절마다 근거 확보 | 적용됨 |
   | fan-out (F1) | 호출 분리 | 분리해도 동일 오류 |
   | 규칙 차단 (b안) | verifier 게이트 | 코퍼스 통계로 사전 기각 |

7. 결론 — **정보 배치로는 넘을 수 없는 벽.** 남은 건 모델 능력.

(b)안 기각은 **수치를 반드시 넣을 것**: 저장된 32문항에서 표 딱지를 인용한
claim 18건 중 진짜 주어 라벨은 2건, 코퍼스 전체 표 1,532개 중 따옴표 도입부는
29개(1.9%). 도입 전에 기각했다는 게 요점이다.

**6-3 slot 25 — verifier 과차단**

가장 정확한 근거를 고른 답이 relevance 임계값에 걸려 차단된 사례.
안전장치가 정답을 죽일 수 있다는 실증.

**6-4 폐기한 개선안**

coverage contract / fan-out / 표 주어 결속 / 규칙 차단.
각각 **왜 폐기했는지 게이트 수치와 함께.**

### 8. 기술 스택과 재현

- 무료·로컬 전용 (Ollama `qwen3-8b:ctx8192`, 유료 API 0회)
- 재현 커맨드는 **실제로 동작하는 것만** 적는다. 확인 없이 적지 말 것

**8-1 코퍼스 스냅샷 — 반드시 넣는다**

문서의 모든 숫자가 어느 코퍼스 기준인지 못박지 않으면 재현 불가능한
주장이 된다. 다음 3항목을 그대로 넣는다.

```
코퍼스 스냅샷   2026-07-17 수집 · 07-18 정규화 · 07-21 청킹
규모            문서 980 · 청크 3,599
갱신 절차       discover_sources → collect_details → 정규화 → 청킹
                → BM25 재빌드 → dense 재임베딩
```

그리고 **왜 갱신이 봉인 평가를 깨지 않는지**를 설명한다. 근거는 실제 코드다.

```python
# src/v3/build_chunks.py:124
payload = (parent_document_id + offset_source + start_offset + end_offset
           + sha256(display_text) + chunker_version)
chunk_id = "chunk_sha256_" + sha256(payload)
```

전역 인덱스도 코퍼스 전체 해시도 들어가지 않는다. 전부 문서-로컬 값이다.
따라서:

- 신규 문서 추가 → 기존 `chunk_id` 전부 유지 → 봉인 평가의 근거 좌표 무효화 없음
- 기존 문서 수정 → **그 문서의 청크만** 새 id

**"현재 최신이다"라고 쓰지 말 것.** 하루만 지나도 거짓이 된다.
쓸 것은 "언제 기준이고, 어떻게 갱신하며, 갱신해도 왜 안 깨지는가"다.

**갱신을 실행하지 말 것.** 코퍼스 갱신은 이 라운드 범위 밖이며 별도
라운드로 예정돼 있다 (§9 참조).
- **데모** — ⚠️ **`app/` 을 커밋하지 말 것. 실행도 하지 말 것.**

  `app/product_free_rag_demo.py`, `app/product_free_rag_api.py`, `app/ui/` 는
  현재 미추적 상태이며 **다른 작업 트랙이 동시에 수정 중이다.**
  여기서 커밋하면 남의 작업 중간 상태를 커밋하게 된다.

  이 절에는 다음만 적는다.

  ```
  데모(웹 UI·API)는 별도 트랙에서 개발 중이며 이 문서 시점에는 미포함.
  ```

  스크린샷·실행법·`app/` 파일 목록 전부 넣지 않는다.
  데모 절은 UI 트랙이 완료된 뒤 별도 라운드에서 추가한다.
