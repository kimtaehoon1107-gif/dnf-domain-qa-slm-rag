## 1. 왜 재도출하는가

W6 5분할은 **overlap 지표 위에서** 만들어졌습니다. 그 지표는 값 누락을
숨긴다는 것이 확인됐습니다.

```
A6-7 골드 좌표  191-224  '…쿨타임이 감소합니다. (20초 → 18초)'
    pack unit  189-212  '…쿨타임이 감소합니다.'
    → 겹침 → "visible" 통과 ✅
    → 20초도 18초도 없음 ❌
```

그 결과 W6의 분류 두 건이 틀렸음이 이미 드러났습니다.

```
A6-1   W6 "근거는 이미 pack에 있음 → 관계 역할"  →  실제 value_present partial
A6-26  사람 판정 "생성 누락"                      →  실제로는 pack에 9,800 세라 없음
```

**남은 로드맵이 전부 W6 분류에 기반하므로, 정확한 표가 필요합니다.**

## 2. 귀속 규칙

실패 요구마다 **처음 실패한 단계**에 귀속하십시오.

```
S1 검색      골드 청크가 최종 후보 8개에 없음
S2 pack      후보엔 있으나 골드 값이 evidence pack에 없음
S3 생성      pack에 값이 있으나 Qwen claim에 그 값이 없음
S4 verifier  claim에 값이 있으나 verifier가 거절
S5 의미      claim이 승인·노출됐으나 사람 판정이 오답
```

`S5`는 **대상·관계 오연결** 계열입니다 (A6-1 네이버페이 한도, A6-22 담당부서·12/4,
A6-7 타이드바운드 12→9).

### 판정 자료

```
S1   골드 청크 순위 진단 222e97a 의 final_candidate 결과 재사용
S2   value_present (M3 / A_current 기준선). 새로 재구성하지 말고 기존 산출물 재사용
S3   저장된 one-shot 결과의 claims + rejected_claims 텍스트
S4   rejected_claims 의 reason 코드
S5   공식 사람 판정 (19/32) 과 노출 답변 대조
```

### 필수 제약

```
□ 21건의 귀속 합계가 정확히 21이어야 한다
□ 각 건에 근거 한 줄을 붙인다 (사람이 재확인 가능하도록)
□ value_present 는 값 유형별로 분리 보고
     numeric · date · time · currency  →  판정 근거
     descriptive (복합 서술형)          →  별도. A6-17·29 위양성 사례 참조
```
