# 지시서 — claim당 evidence_refs 최소성 조사 및 정리

작성: 2026-08-12
Qwen 호출 예산: P0~P1 **0회** (저장된 artifact 재분석만) · P2 구현 **0회** · P3 검증에서만 사용 (adaptive 최대 32회)

---

## 0. 문제

프롬프트에는 이미 최소성 지침이 있다.

```
src/v3/product_free_rag.py:111
"각 claim에는 짧고 직접적인 text와 이를 지지하는 최소 evidence_refs만 넣으세요."
```

**그런데 실제로는 지켜지지 않는 사례가 있다.** 데모 질문 세트 10번(미카엘라 이벤트 기간)을
API로 직접 실행해 확인했다.

```
질문       그릇된 신념으로 빚어진 성역에서 미카엘라를 마주하라 이벤트 기간이 언제까지야?
claim      "이벤트 기간은 2026년 8월 6일(목) 점검 후 ~ 8월 20일(목) 점검 전입니다."
evidence_refs  [E1, E3, E4, E5, E6, E7, E8]   ← 7개 전부
```

실제로 기간을 증명하는 건 **E3** 하나뿐이다("이벤트 종료일인 8월 20일(목) 06시에는
초기화되지 않습니다"). 나머지 6개는 같은 문서에서 나온, 질문과 무관한 내용이다.

```
E1   우편 보관 기간 15일 (보상 지급 방식 — 기간과 무관)
E4   "보상 실명 자세히 보기" (버튼 라벨 파편, 문장도 아님)
E5   레이드 클리어 미션 명성 조건
E6   누적/주간 미션 초기화 규칙
E7   "던파 공식 홈페이지 > MY > 마이페이지 > 마이캐릭터 > 타임라인" (내비게이션 경로 파편)
```

값 자체는 틀리지 않았다. 문제는 **인용 카드가 "이걸 다 읽어야 진짜 근거를 찾을 수 있는"
상태**가 된다는 것이다. 이 프로젝트가 내세우는 "근거를 정직하게 보여준다"는 정체성과
어긋난다.

---

## 1. 기존에 이미 있는 것 (재발명 금지)

`src/v3/product_minimal_verifier.py:1662-1688` 에 evidence_refs를 **가지치기하는
기존 경로**가 이미 있다.

```python
pruned_evidence_refs = set()
...
citations, selected_units, condition_pruned_refs = (
    _matching_explicit_condition_evidence(question, citations, selected_units)
)
```

**그런데 이 함수는 "질문에 명시된 조건(난이도·등급 등)과 안 맞는 근거"만 골라낸다.**
이번 사례처럼 질문에 조건절이 아예 없는 경우(단순 기간 질문)에는 아무것도 걸러내지
못한다. 새 함수가 필요한 게 맞는지, 이 함수를 확장하는 게 맞는지는 P0/P1에서 판단한다.

**하지 말 것: 새 파일이나 새 클래스부터 만들지 말 것.** 이미 있는 pruning 계열
(`_matching_explicit_condition_evidence`, `pruned_evidence_refs`, `rebound_evidence_refs`)
과 `_surface_overlap` / `_claim_addresses_question_surface`(오늘 커밋 `b18001f`,
`ecf7f6e`에서 확장된 그 함수들) 를 먼저 읽고, 같은 계열에 넣을 수 있는지부터 본다.

## 2. P0 — 실태 조사 (변경 0, Qwen 0)

### 조사 항목

1. **claim당 evidence_refs 개수 분포**
   - 저장된 실행 artifact 전부(`reports/v3/product_free_rag_*.jsonl`,
     A6 sealed one-shot, A6 adaptive replay 포함)에서 claim 하나당 evidence_refs
     개수를 센다.
   - 몇 개 이상이면 "많다"고 볼지 임의로 정하지 말고, 분포 자체(평균·중앙값·최댓값·
     히스토그램)를 먼저 보여준다.

2. **"근거 없는 근거"가 실제로 몇 개인가**
   - evidence_refs 개수가 3개 이상인 claim을 모아, 각 evidence_ref의 원문
     텍스트와 claim text 사이에 표면 어휘 중첩(`_surface_overlap` 재사용)이
     있는지 계산한다.
   - "중첩 없는 evidence_ref"의 비율을 claim 단위·전체 단위 둘 다로 낸다.

3. **sealed A6 32문항에서의 영향**
   - sealed 저장 출력에서 이 패턴이 몇 건인지, 그 claim들의 사람 감수 판정
     (20/32에 들어간 것들)이 이 문제와 관련 있는지 대조한다.
   - **여기서 하나라도 건드리면 봉인 규율 위반이다. 읽기만 한다.**

4. **오탐 위험 — 진짜로 여러 근거가 필요한 경우와 구분**
   - 표 비교/복수 요구 질문(예: "가격과 기간을 함께" 유형)처럼 **여러 evidence_ref가
     전부 정당하게 필요한 claim**도 있다. 이런 claim들이 3번 항목의 "많다" 분포에서
     같이 잡히는지 확인하고, 오탐 사례를 최소 5개 이상 골라 표로 제시한다.

### P0 게이트

- [ ] 파일을 하나도 수정하지 않았다
- [ ] Qwen을 호출하지 않았다 (저장된 artifact만 사용)
- [ ] 4개 항목 전부 수치로 답했다
- [ ] "정말 여러 근거가 필요한 정상 사례"와 "과다 인용"을 구분하는 기준을
      최소 1개 이상 제시했다 (직관 아니라 측정 기준으로)

산출물: `reports/v3/claim_evidence_ref_minimality_survey_20260812.json`

## 3. P1 — 설계안 제시 (구현 전 승인 필요)

P0 결과를 근거로 아래를 정한다. **임의로 구현 착수 금지.**

```
· 기존 pruning 함수를 확장할지, 새 함수를 추가할지 — 이유와 함께
· 판정 규칙 (예: evidence_ref 원문과 claim text의 표면 중첩이 0이면 제거,
  단 남은 evidence_refs가 0개가 되면 원래대로 유지)
· 이 규칙이 정상적인 "복수 근거 필요" claim(표/복수요구)을 건드리지 않는지
  P0에서 찾은 오탐 사례로 직접 검증
· 봉인 A6 sealed 저장 출력 재채점에 영향이 있는지 (없어야 한다 — 있으면
  그 자체가 큰 발견이니 별도로 보고)
```

**P1 게이트**

- [ ] 규칙이 P0 수치·사례에 근거한다
- [ ] 정상적인 복수-근거 사례를 오탐으로 잘못 자르지 않는다는 근거를 제시했다
- [ ] 구현을 시작하지 않았다

## 8. 이 라운드의 성격

**결론이 "지금 구조가 맞다, 건드리지 않는다"여도 성공이다.** P0에서 "과다 인용이
드물고, sealed 20/32에 영향이 없다"는 게 나오면 그것도 유효한 결과다. 목적은
**claim 하나에 근거가 여러 개 딸려오는 게 정상 범위인지 결함인지를 수치로 아는 것**이다.

측정 없이 고치는 것보다, 재고 안 고치는 편이 낫다.
