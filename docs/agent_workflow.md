# Subagent Workflow

이 문서는 던파 문서 기반 LLM 프로젝트에서 사용할 서브에이전트 구성을 정의한다.
목표는 작업을 크게 `Debug Agent`, `Review Agent`, `Research Agent`로 나누어
문제 해결, 검토, 자료 조사 책임을 명확히 분리하는 것이다.

## 공통 원칙

- 모든 에이전트는 던파 공식 문서, 수집 데이터, 평가셋, 코드 실행 결과처럼 확인 가능한 근거를 우선한다.
- 추측이 필요한 경우 추측임을 명시하고, 근거가 부족하면 작업을 중단하거나 보류 의견을 낸다.
- 프로젝트 범위를 벗어나는 기능 제안, 대규모 리팩터링, 평가 기준 변경은 요청 없이 수행하지 않는다.
- 최종 답변이나 변경 제안에는 확인한 파일, 명령, 데이터 경로를 함께 남긴다.

## 사용 시점 요약

| 상황 | 권장 에이전트 |
|---|---|
| 테스트 실패, 예외, 검색 품질 저하, 평가 지표 급락 | Debug Agent |
| 코드/문서/데이터셋 변경 검토, PR 리뷰, 회귀 위험 점검 | Review Agent |
| 던파 공식 문서 조사, 근거 수집, 새로운 QA/평가 문항 설계 | Research Agent |

## Debug Agent

### 역할

Debug Agent는 프로젝트의 실행 실패나 품질 저하 원인을 좁히고 재현 가능한 수정 방향을 제시한다.
대상은 수집, 청킹, 인덱싱, 검색, 답변 생성, 평가, LoRA/QLoRA 스모크 실행까지 포함한다.

### 입력

- 실패한 명령어와 전체 에러 로그
- 관련 파일 경로와 최근 변경 내용
- 재현 데이터 샘플 또는 문제 질의
- 기대 동작과 실제 동작
- 가능하면 실패 전후의 평가 지표

### 출력

- 재현 절차
- 원인 후보와 확인 결과
- 최소 수정안
- 검증 명령어
- 남은 위험 또는 추가 확인이 필요한 항목

### 금지사항

- 재현 없이 원인을 단정하지 않는다.
- 관련 없는 파일을 정리하거나 리팩터링하지 않는다.
- 평가셋을 수정해서 실패를 숨기지 않는다.
- 근거 없는 하이퍼파라미터 변경으로 문제를 덮지 않는다.
- 사용자 데이터, API 키, 개인 계정 상태를 추정하지 않는다.

### 사용 시점

- `src/build_index.py`, `src/retrieve.py`, `src/evaluate.py` 실행이 실패할 때
- retrieval `hit_rate@k`, MRR, citation accuracy가 갑자기 낮아졌을 때
- Gradio 앱에서 근거가 비어 있거나 엉뚱한 문서를 인용할 때
- RAFT 데이터 생성 또는 LoRA 스모크 실행이 중단될 때

### 예시 프롬프트

```text
Debug Agent로 동작해줘.
다음 명령이 실패했어:
python src/evaluate.py --eval data/processed/official_eval_set.jsonl

에러 로그와 관련 파일을 보고 원인을 재현한 뒤,
최소 수정안과 검증 명령어를 제안해줘.
평가셋을 바꿔서 실패를 숨기지는 말아줘.
```

```text
Debug Agent로 동작해줘.
공식 문서 chunk 인덱스에서 hit_rate@5가 이전보다 크게 떨어졌어.
최근 변경 파일은 src/prepare_chunks.py와 src/build_index.py야.
지표 하락 원인 후보를 좁히고 재현 가능한 확인 순서를 작성해줘.
```

## Review Agent

### 역할

Review Agent는 변경 사항이 프로젝트 목표와 맞는지 검토하고, 버그, 회귀, 누락된 테스트,
데이터 누수, 근거 없는 답변 생성 위험을 우선순위로 지적한다.
단순 취향이나 스타일 선호보다 실제 품질과 유지보수 위험을 중심으로 리뷰한다.

### 입력

- 변경 diff 또는 PR 링크
- 변경 의도와 성공 기준
- 관련 테스트 또는 평가 결과
- 영향을 받는 데이터 파일, 모델 실행 경로, 문서
- 리뷰에서 특히 봐야 할 위험 영역

### 출력

- 심각도 순으로 정렬된 리뷰 코멘트
- 파일과 줄 번호가 포함된 구체적 지적
- 누락된 테스트 또는 검증 제안
- 문제가 없을 경우 남은 리스크와 확인한 범위
- 필요하면 작은 수정 제안

### 금지사항

- 요청받지 않은 리팩터링을 리뷰 범위에 포함하지 않는다.
- 근거 없이 "좋아 보임" 또는 "나빠 보임"으로 판단하지 않는다.
- 사소한 스타일 코멘트를 중요한 버그보다 앞세우지 않는다.
- 프로젝트의 핵심 목표인 grounded QA와 answerability를 약화하는 변경을 승인하지 않는다.
- 실제 diff에 없는 문제를 가정해 지적하지 않는다.

### 사용 시점

- retrieval, answer generation, evaluation 로직 변경 후
- 공식 eval/train split, RAFT 데이터 생성 로직 변경 후
- 문서나 포트폴리오 설명이 실제 구현과 어긋날 가능성이 있을 때
- PR 생성 전 회귀 위험을 점검할 때

### 예시 프롬프트

```text
Review Agent로 동작해줘.
이번 diff는 official eval 생성 로직 변경이야.
데이터 누수, expected_chunk_ids 처리, answerability label 보존 여부를 중심으로 리뷰해줘.
코멘트는 심각도 순서로 파일/줄 번호와 함께 작성해줘.
```

```text
Review Agent로 동작해줘.
Gradio 앱에서 검색 근거 표시 방식을 바꿨어.
사용자에게 unsupported answer를 확정적으로 말하는 회귀가 없는지,
그리고 citation이 비어 있을 때 UI가 오해를 만들지 않는지 검토해줘.
```

## Research Agent

### 역할

Research Agent는 던파 공식 문서와 프로젝트 내부 데이터에서 근거를 수집하고,
문서 기반 QA, 평가 문항, 라벨링 기준을 설계하는 역할을 맡는다.
답변 생성보다 근거 정리와 출처 추적을 우선한다.

### 입력

- 조사할 주제, 던파 시스템, 이벤트, 공지 유형
- 필요한 산출물 형식
- 사용할 수 있는 문서 경로 또는 공식 출처
- 포함해야 할 기간, 서버, 버전, 캐릭터, 아이템 범위
- 제외해야 할 비공식 출처나 추측 영역

### 출력

- 확인한 출처 목록
- 핵심 사실 요약
- QA 후보 또는 eval row 초안
- evidence span, expected_doc_id, expected_chunk_id 후보
- 근거 부족 또는 추가 수집 필요 항목

### 금지사항

- 공식 문서에 없는 보상, 날짜, 수치, 정책을 만들어내지 않는다.
- 커뮤니티 글이나 추측성 정보를 공식 사실처럼 취급하지 않는다.
- 최신성이 필요한 정보는 수집일 또는 문서 기준일 없이 단정하지 않는다.
- 개인 계정 상태, 경매장 시세, 실시간 서버 상태를 답변하지 않는다.
- 근거 문서와 연결되지 않은 QA를 평가셋에 넣지 않는다.

### 사용 시점

- 새로운 공식 문서를 수집해 QA 후보를 만들 때
- 라벨링 가이드에 들어갈 예시를 보강할 때
- 평가셋의 `gold_answer`, `evidence_span`, `expected_chunk_id`를 설계할 때
- 모델 답변이 공식 문서 근거와 일치하는지 확인할 때

### 예시 프롬프트

```text
Research Agent로 동작해줘.
data/raw/official_docs.jsonl에서 세라샵 또는 결제 관련 문서를 찾아
answerable QA 후보 5개와 unanswerable QA 후보 3개를 만들어줘.
각 항목에는 evidence_span과 expected_doc_id 후보를 포함해줘.
```

```text
Research Agent로 동작해줘.
던파 공식 공지 문서 기준으로 "이벤트 보상 지급 조건" 질문에 답할 수 있는 근거를 찾아줘.
공식 문서에 없는 조건은 추측하지 말고, 근거 부족 항목은 별도로 표시해줘.
```

## 권장 작업 흐름

1. Research Agent가 근거 문서와 QA 후보를 정리한다.
2. Debug Agent가 수집, 청킹, 인덱싱, 검색, 평가 실행 문제를 재현하고 수정한다.
3. Review Agent가 변경 diff와 평가 결과를 검토해 회귀 위험을 확인한다.

이 순서는 고정 규칙이 아니다. 실패 원인이 이미 명확하면 Debug Agent부터 시작하고,
변경이 완료된 상태라면 Review Agent만 호출해도 된다.
