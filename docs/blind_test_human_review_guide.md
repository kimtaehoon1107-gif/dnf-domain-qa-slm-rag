# Blind Test 사람 검수 가이드

## 목적

검색기나 SLM을 실행하지 않은 상태에서 blind-test 후보를 검수한다. 실제 사용자가 물을 만한 자연스러운 질문이며, 기록된 근거로 정답과 answerability를 판정할 수 있는 행만 승인한다.

## 입력 항목

최소한 아래 세 열을 작성한다.

- `human_decision`: `approve`, `rewrite`, `reject` 중 하나
- `rewritten_question`: `rewrite`를 선택한 경우 수정 질문
- `review_notes`: 수정·거절 이유 또는 애매한 점

가능하면 아래 품질 열도 `yes` 또는 `no`로 작성한다.

- `question_natural`: 실제 사용자 질문처럼 자연스러운가
- `evidence_alignment`: 질문이 evidence span의 사실을 정확히 묻는가
- `answerability_correct`: `true`, `partial`, `false` 라벨이 맞는가
- `expected_answer_correct`: expected answer가 근거로부터 직접 도출되는가

## 판정 기준

### approve

다음 조건을 모두 만족할 때만 승인한다.

- 질문이 실제 사용자가 물을 만한 자연스러운 문장이다.
- 하나의 식별 가능한 사실이나 판단 경계를 묻는다.
- expected answer가 evidence span으로 직접 뒷받침된다.
- `true`, `partial`, `false` 라벨이 적절하다.
- 문서 제목만 보고 정답을 맞힐 수 있는 질문이 아니다.
- 시점에 따라 달라지는 질문에는 충분한 날짜나 기준 시점이 있다.

### rewrite

근거와 라벨은 쓸 수 있지만 질문이 어색하거나, 너무 넓거나, 중복되거나, 근거와 살짝 어긋난 경우 선택한다. 원래 사실과 answerability 라벨은 유지하고, 근거에 없는 내용을 추가하지 않는다.

현재 샘플에서 특히 확인할 예시는 다음과 같다.

- `비인가 프로그램 사용 주의사항은 뭐야 이용 조건이 뭐야?`: 질문 종결 표현이 두 번 들어갔다.
- `장비 관련 변경 문서에서 꼭 알아둘 내용이 뭐야?`: 근거는 아이템 품질 등급인데 질문 범위가 지나치게 넓다.
- `인벤토리 의외 문서에서 꼭 알아둘 내용이 뭐야?`: 문장이 문법적으로 깨져 있다.
- `기간제 정보창 일정이 어떻게 돼?`: 근거는 삭제 일정을 확인하는 위치이지 일정 자체가 아니다.
- `아이템 삭제 일정 날짜나 시간을 정확히 알려줘.`: 어떤 아이템인지 질문에 명시해야 한다.

### reject

목표 사실을 바꾸지 않고는 고칠 수 없거나, evidence span이 불완전·오래됨·모순·무관한 경우 거절한다.

## Answerability 확인

- `true`: 근거만으로 간결한 정답 전체를 제공할 수 있다.
- `partial`: 사실 부분은 답할 수 있지만 개인 추천, 예측, 계정별 판단 등은 거절해야 한다.
- `false`: 수집된 공식 문서로 답할 수 없다. citation과 evidence는 비어 있어야 한다.

## 동결 조건

검수 중에는 후보 파일을 retrieval이나 SLM에 입력하지 않는다. 30행 샘플을 수정한 뒤 같은 기준으로 100행 전체를 검수한다. 승인된 파일과 새 SHA-256을 manifest에 기록한 후에만 one-shot 최종 blind test로 사용한다.
