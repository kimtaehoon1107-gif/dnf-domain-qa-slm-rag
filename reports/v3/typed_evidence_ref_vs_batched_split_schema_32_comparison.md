# 32문항 paired 비교: split-schema vs typed evidence-ref

## 결론

같은 32문항, 같은 `subject_arm_full` 후보, 같은 Qwen3 8B에서 typed
evidence-ref가 이겼다.

| 지표 | Arm A: batched split-schema | Arm B: typed evidence-ref |
|---|---:|---:|
| 후보 보유 | 31/32 | 31/32 |
| 의미상 완전 정답 + 직접 근거 | 22/32 | **30/32** |
| 안전한 부분답·보류 | 9/32 | **2/32** |
| 실제 false-full | 1/32 | **0/32** |
| full 응답 | 23 | **30** |
| partial 응답 | 6 | 2 |
| abstain | 3 | **0** |
| LLM 호출 | 32 | 32 |
| 평균 시간 | **19.95초** | 20.33초 |
| p50 | 18.74초 | **18.12초** |
| p95 | 42.10초 | **38.58초** |
| 최대 | **48.39초** | 54.15초 |
| 전체 토큰 | 166,600 | **149,937** |

완전 정답은 8문항 순증했고 실제 false-full은 1건에서 0건으로 줄었다.
평균 시간은 0.38초 느려졌지만 p50과 p95는 더 빨랐고, 전체 토큰은
16,663개(약 10.0%) 감소했다.

## 무엇이 개선됐나

Arm A에서 실패했던 9개가 Arm B에서 완전 정답으로 바뀌었다.

```text
7, 8, 12, 13, 17, 20, 22, 24, 29
```

주된 이유:

- 모델이 quote를 다시 복사하지 않고 evidence ref만 선택
- 날짜·백분율·boolean을 typed value로 정규화
- 서버가 정확한 원문 좌표를 복원
- subject·relation 문맥을 heading과 목록 도입문으로 연결
- 게시 시각과 적용일 같은 temporal role을 구분

특히 7번은 Arm A가 게시 시각을 적용일로 노출한 실제 false-full이었다.
Arm B는 적용일을 직접 말하는 근거를 선택해 완전 정답으로 바꿨다.

## 남은 회귀

14번은 Arm A가 두 boolean 요구를 정확히 답했지만 Arm B 모델이 캐릭터 스킬
반영 여부를 `true`로 출력했다. verifier가 부정 원문과 충돌한다고 판단해 해당
요구만 숨겼다.

따라서 14번은 틀린 full이 아니라 안전한 partial이다. 이 한 문항에 맞춘 규칙은
추가하지 않고 새 평가에서 같은 유형이 반복되는지 확인하는 것이 맞다.

## 판정 범위

이 paired 비교에서는 Arm B가 명확히 우세하다. 다만 이 32문항은 반복 개발에
사용한 adaptive 세트이므로 다음 주장까지만 가능하다.

```text
가능: 기존 32문항에서 Arm B가 Arm A보다 낫다.
불가능: 처음 보는 질문에서도 93.75%가 재현된다.
```

새 질문 평가 전에는 일반화 성능이나 production 성능으로 부르지 않는다.
