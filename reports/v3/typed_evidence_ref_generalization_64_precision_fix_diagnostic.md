# Generalization-64 verifier 정밀도 수정 사후 진단

## 판정 범위

이 결과는 봉인 평가의 새 점수가 아니다. 기존 후보군과 Qwen3 8B 원출력을
그대로 재사용하고, 현재 verifier와 scorer만 적용한 `post-hoc diagnostic`이다.

```text
새 LLM 호출: 0
검색 재실행: 0
기존 후보군 재사용: 64/64
기존 모델 출력 재사용: 64/64
원래 봉인 결과: 37/64 = 57.8% (영구 기록)
```

## 진단 결과

```text
내용 완전 정답: 37/64 -> 40/64 (+3)
correct / incorrect / no_response:
  37 / 7 / 20 -> 40 / 7 / 17
verifier_overreject: 14 -> 9
generation_error: 3 -> 3
false-full: 1 -> 1
후보 보유: 54/64 -> 54/64
인용 좌표 exact: 100% -> 100%
```

## 정답으로 복구된 문항

| 슬롯 | 복구된 값 | 원인 |
|---:|---|---|
| 12 | `광휘의 잔영 120개`, 월 4회 | 단위-우선 통화 수량 인식 |
| 15 | DirectX11 문제 수정 `예` | `수정됩니다` 긍정 인식 |
| 35 | 다른 계정 이동 시 교환불가 변경 `예` | `교환불가` 상태명사 보호 |
| 58 | 다른 계정과 교환 가능 `예` | `교환가능` 긍정 인식 |

## 새로 발견된 회귀

슬롯 38은 `correct -> incorrect`로 회귀했다.

```text
질문:
고블린패드 신규 발급은 언제 중단됐고, 기존 이용자는 재발급할 수 있어?

모델 값:
True

정답 근거 E4:
기존 이용 중이신 경우 비밀번호 변경, 재발급이 가능합니다.

모델이 함께 선택한 방해 근거 E10:
폐기 시 추가 발급이 가능하지 않은 점 참고 부탁드립니다.
```

현재 boolean verifier는 선택한 근거들을 합친 뒤 부정을 우선한다. 따라서
관계가 다른 E10의 부정이 정답 근거 E4의 긍정을 덮었다. boolean 방향은 전체
선택 근거를 하나로 합치지 말고, subject·relation이 맞는 개별 evidence unit에서
판정해야 한다.

## 승인됐지만 여전히 정답 처리되지 않은 문항

| 슬롯 | verifier 출력 | 남은 문제 |
|---:|---|---|
| 52 | `22600` | 정답은 `22,600 세라`; currency 답변에 단위 복원이 없음 |
| 54 | `10` | 정답은 `10 골드 코인`; currency 답변에 단위 복원이 없음 |

두 문항은 금액이 선택 근거에 실제 존재하므로 verifier 차단에서는 벗어났다.
그러나 서버가 `currency`의 단위를 답변에 복원하지 않아 scorer가 완전한
통화 값으로 인정하지 않았다. 현재 단위 복원은 `price`에만 적용되므로
`currency`에도 같은 단일 매칭 규칙을 적용해야 한다.

## 결론

이번 수정은 의도한 4문항을 실제로 복구했지만, boolean 복수 근거 결합에서
1문항 회귀가 생겨 순개선은 `+3`이었다. 또한 통화 2문항은 verifier 승인까지만
복구되고 최종 answer rendering이 미완성이다.

다음 수정 후보는 두 가지로 좁혀진다.

1. boolean을 relation-compatible evidence unit별로 판정
2. 숫자형 `currency`에 선택 근거의 유일한 통화 단위 복원

수정하더라도 이 64문항은 계속 진단 세트로만 사용하고, 일반화 성능은 새
홀드아웃에서 측정해야 한다.
