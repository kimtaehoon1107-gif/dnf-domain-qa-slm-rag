# Typed evidence-ref Subject Arm 32문항 의미 재검수

## 결론

이 Arm은 현재 adaptive 32문항에서 가장 좋은 실험 결과다.

```text
Subject-anchored 검색
→ 질문당 동일 스키마 요구를 한 번에 생성
→ 비표: typed value + evidence_ref
→ 표: 기존 table-row branch
→ relation/context-aware verifier
→ Qwen3 8B ctx8192
```

실제 답 내용과 공식 근거를 사람이 다시 대조한 결과:

| 지표 | 이전 최선 batched split-schema | Typed evidence-ref |
|---|---:|---:|
| 후보 보유 | 31/32 | 31/32 |
| 의미 기준 완전 정답 | 22/32 | **30/32** |
| 의미 기준 부분답 | 9/32 | **2/32** |
| 의미 기준 실제 false-full | 1/32 | **0/32** |
| LLM 호출 | 32 | 32 |
| 평균 응답 시간 | 19.95초 | 20.33초 |
| 총 토큰 | 166,600 | **149,937** |
| 생성 오류 | 0 | 0 |
| 인용 원문 좌표 일치 | 100% | 100% |

정답률은 `68.75% → 93.75%`로 8문항 개선됐고, 실제 false-full은 `1 → 0`으로 감소했다. 평균 지연은 0.38초 증가했으며 총 토큰은 10.0% 감소했다.

이 결과는 반복 개발에 사용한 adaptive 세트 결과이며 독립 blind 성능으로 부르면 안 된다. 현재 Arm을 차기 기준선 후보로 삼는 것은 GO지만, 라이브 자동 승격은 하지 않는다.

## 자동 지표와 의미 판정의 차이

최종 자동 지표는 다음과 같다.

- all-required evidence: `26/32`
- literal gold span: `25/32`
- candidate-covered literal: `25/31`

자동 false-full로 표시된 문항은 `12, 21, 23, 30, 32`다. 그러나 다섯 문항은 모두 실제 내용상 정답이다.

| 문항 | 자동 실패 이유 | 의미 판정 |
|---:|---|---|
| 12 | 첫 구매 혜택 gold가 상품명 외 상세 사용 설명까지 긴 span으로 묶음 | 요구한 혜택 상품명과 삭제 시각을 정확히 답함 |
| 21 | gold는 운영정책 문장, 출력은 공식 게임가이드의 동등·상세 문장 | 정답 |
| 23 | gold는 요약 문장, 출력은 05시/07시 예시가 포함된 공식 동등 문장 | 정답 |
| 30 | 날짜 표기와 필드 표현 차이 | 거래 타입과 삭제 시각 모두 정답 |
| 32 | 자연어 gold 대신 정확한 표 행을 인용 | 거래 타입·삭제 시각·획득 구성 모두 정답 |

따라서 이 다섯 문항을 실제 false-full로 집계하면 안 된다.

### 5번

질문은 던파ON 2.0.19의 적용일과 다운로드 시작 시각을 함께 요구했다.

- 다운로드 시작 시각 `2026-06-25 09:00`: 정확히 답함
- 적용일: 모델 값은 `2026-06-25`로 맞았지만 다운로드 문장을 근거로 선택
- verifier가 `effective_at`과 `download_start` 역할 불일치를 감지해 적용일만 차단

최종 판정은 안전한 partial이다.

### 14번

질문은 캐릭터 스킬 반영 여부와 유틸 전용 장비 점수 계산 여부를 요구했다.

- 유틸 전용 장비 계산 여부: `아니오`, 정확함
- 캐릭터 스킬 반영 여부: 원문은 미반영인데 모델이 `true`를 출력
- boolean typed verifier가 부정 근거와 양의 값 충돌을 감지해 해당 요구만 차단

최종 판정은 안전한 partial이다.

## 이번 변경이 해결한 것

### 1. quote 복사 오류 제거

모델은 원문 문장을 다시 복사하지 않고 `E3` 같은 ID만 고른다. 서버가 해당 ID를 정확한 chunk 좌표로 복원하므로 공백·불릿·조항 번호 차이로 정상 답이 차단되지 않는다.

### 2. 구조화 값만 typed 검증

날짜, 시각, 기간, 백분율, 가격, 숫자, boolean은 정규화해 원문 값과 비교한다.

- `20`과 `20%`를 안전하게 정규화
- `4,000만 골드`와 `40,000,000 골드`를 같은 값으로 검증
- 적용일과 게시일·다운로드 시각을 구분
- 부정 근거에 `true`를 붙인 답은 차단

### 3. 자연어는 선택한 원문으로 서버가 답변

정의, 절차, 정책 사유, 상태 변경 같은 자유문장은 모델의 재서술을 노출하지 않는다. 모델이 고른 정확한 evidence unit을 서버가 그대로 답변으로 사용한다.

이 방식으로 다음 문제가 사라졌다.

- `수정됨`과 `수정됩니다`의 문자열 차이
- 한국어 원문을 영어로 재서술하는 문제
- 답변 토큰 전체가 인용에 있어야 한다는 과잉 검증

### 4. 문서 구조 문맥을 정확한 좌표로 결합

목록 값 행만 선택해도 바로 위의 목록 도입문과 상위 Markdown heading을 서버가 연결한다.

예:

```text
해방된 흉몽(챌린지) ... 다음 버프가 적용됩니다.
→ 공격속도 20% 증가

트로피컬 바캉스 패키지 첫 구매 시 아래 선물을 드립니다.
→ 열대야의 추억 오라 확정 변경권

길드 콘텐츠에서 아래 행위가 확인되면 길드가 해제될 수 있습니다.
→ 명예훼손 / 사칭·사기 / 영리 홍보 행
```

문맥도 실제 원문 좌표로 인용되므로 숨은 의미 추론만으로 통과시키지 않는다.
